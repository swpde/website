1 · 展开存储体：整个 Cache → 组 → 路 / 行 → 字节

Cache 存储体的逻辑形状

框内的一条横排代表一条缓存行。Data 中的数字是字节偏移编号，不是字节内容；实际数据值在下面第 3 部分显示。省略号表示还有其他组 / 字节。

一组中的 Way 0 和 Way 1 是两条不同的缓存行；“2 路”不是“一行分成两半”。同一个 Way 编号贯穿所有组，构成一路；每组在该路中都有一条行。

C = S × E × B 是可存放的数据字节数，不包括 tag、valid、dirty 和替换状态等元数据。改参数会清空本页演示状态。地址宽度固定为 32 位。

对原文的四处补充与纠正

valid 不是页表映射状态

valid 表示这条缓存行当前保存着可参与命中判断的有效缓存内容。它不直接表示操作系统是否为某个虚拟地址建立了页表映射。

多个内存块映射到同一组

相同组索引、不同 tag 的内存块会竞争该组的 E 条缓存行。同一内存块里的多个字节则共用一条缓存行，靠 offset 区分。

miss 不等于一定访问 DRAM

查找的这一级 Cache 缺失后，会请求下一存储层次。它可能在下一级缓存命中；通常按缓存行填充，并返回 Load 所需数据。

CPU Cache 与 Linux 页缓存分开理解

这张图说明的是硬件 CPU Cache。Linux page cache 是操作系统管理的文件页缓存，二者有关联，但结构和管理机制不同。

模型范围、公式与 RSD 参数来源

本页演示普通、可缓存、已完成地址转换的字节读取。将输入地址当作缓存索引和 tag 使用的地址，不模拟虚拟地址转换、跨行访问、写回、预取和一致性。

b = log₂(B)，s = log₂(S)，t = 32 − s − b
offset = address mod B
set = floor(address / B) mod S
tag = floor(address / (B × S))
blockBase = floor(address / B) × B

替换策略采用 LRU（优先替换最久未访问的有效行），先使用无效行。这只是本页教学选择，不代表 RSD 的实际替换算法。演示按钮 ④ 会执行一串映射到同一组的访问，使该组发生替换。

已核对当前 RSD MicroArchConf.sv：ICache / DCache 均为 WAY_NUM = 2、INDEX_BIT_WIDTH = 9 − log₂(2) = 8、LINE_BYTE_NUM = 8，因此 S = 256，E = 2，B = 8，C = 4096 B。
